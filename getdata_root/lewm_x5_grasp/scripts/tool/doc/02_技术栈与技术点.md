## 1. 技术栈（确认版）

| 层级 | 选型 | 说明 |
|------|------|------|
| 语言 | Python 3.10+ | 与 ROS2 Humble client 一致 |
| 臂状态 | `rclpy` + `/arm_status` | `joint_pos`、`end_pos` |
| 3D 主界面 | **MuJoCo**（`mujoco` + `mujoco.viewer` 或被动查看器） | 加载已有 X5 URDF/MJCF |
| 机器人模型 | `x5.urdf`（7.12eval：`ROS2/X5_ws/.../x5.urdf` 等） | 与控制器同源模型优先 |
| 正运动学 | **主路径**：`q_cmd`（或 `joint_pos`）→ MuJoCo FK → 复现末端 | 见 `01` §3 |
| SDK 参考 | 可选：`/arm_status.end_pos` 画第二套轴 | 真机实测，非主需求 |
| 图像 | 复用 client 推送的 RGB / RealSense | 子窗或 MuJoCo overlay 旁路用 OpenCV/matplotlib 2D |
| 采集参考 | `h5py` 读 HDF5 | eef / qpos / images |
| 策略接入 | hook / 帧总线写入 `eval_starvla_libero_x5.py`（7.12eval） | 边跑边看 |
| 回放扩展 | 抽象 `FrameSource` 接口 | 第一期只实现 `LivePolicySource` |

### 1.1 为什么用 MuJoCo 而不是只画 Matplotlib 轴

- 需要 **整臂 3D** 与坐标轴一起看，URDF 已有。  
- MuJoCo 可直接用关节角驱动，和真机 `joint_pos` / `q_cmd` 对齐。  
- 仍可用极简 Matplotlib 做调试，但 **交付 UI 以 MuJoCo 为准**。

### 1.2 代码布局

```text
scripts/tool/x5_play_viz/
  viz_app.py      CLI
  mj_model.py     URDF 加载 + set q_cmd
  axes.py         画轴 / HDF5 鬼臂
  image_panel.py  OpenCV cam_high|cam_wrist 侧窗
  hdf5_ref.py     采集 HDF5 字段探测
```

日常命令见 `doc/04_真机启动命令_含UI.md`。

### 1.3 URDF 路径（候选）

优先顺序（实现时探测存在性）：

1. `$ARX_X5_ROOT/ROS2/X5_ws/src/arx_x5_ros2/arx_x5_controller/x5.urdf`  
2. `$ARX_X5_ROOT/py/arx_x5_python/bimanual/script/x5.urdf`  
3. 环境变量 `X5_URDF_PATH` 覆盖  

若只有 URDF、无 MJCF：用 MuJoCo 的 URDF 编译加载（或一次性转 MJCF 缓存到 `tool/assets/`）。

## 2. 核心技术点

### 2.1 关节目标 → MuJoCo FK 复现末端（主路径）

```text
策略/IK ──► q_cmd ──► MuJoCo set qpos ──► FK ──► T_ee_model ──► 画轴 + 整臂
                │
                └─（可选）与策略想要的 EEF / target 同窗对比

joint_pos（反馈）──► 同模型驱动「当前构型」（无 q_cmd 时的退化）
end_pos（可选）  ──► T_ee_sdk ──► 第二套轴（真机报告）
```

- **目的**：看见「解算得到的关节角」在模型里对应的末端，不是为了做 SDK↔URDF 对账产品。  
- 若同显 SDK：标清图例即可；数值差大时属已知现象。

### 2.2 基座轴

- 在 MuJoCo 世界系 / `base_link` 处画 RGB→XYZ 轴。  
- 与机器人模型一同显示。

### 2.3 从 HDF5 还原采集轴

典型字段（以实现时探测为准）：

- `observations/qpos` 或 `action` 相关关节；  
- `observations/eef`（SDK 系末端）；  
- 图像：`observations/images/cam_high` 等或压缩字节。

技术点：

- 用采集帧的 `qpos` 驱动 **第二份**（半透明）MuJoCo 模型或仅画参考轴；  
- 参考图像显示在侧栏；  
- 帧索引：CLI `--hdf5 path --ref-frame 0` 或「锁定首帧作定义参考」。

### 2.4 与 `eval_starvla_libero_x5.py` 同步

推荐数据流：

```text
eval 主循环每步:
  publish VizFrame { joints, end_pos, images, meta }
       │
       ▼
  /tmp/x5_play_viz/latest.npz  (atomic replace)
       │
       ▼
  mujoco_viz 进程 轮询 / 或 ZMQ
```

或同进程：`viz.pump()` 非阻塞（MuJoCo 被动更新），避免拖死控制环。

**约束**：可视化失败不得中断发令；`try/except` 包裹。

## 4. 风险

| 风险 | 缓解 |
|------|------|
| URDF→MuJoCo 网格/关节名不匹配 | 启动时打印 joint 名映射表；提供 `--urdf` |
| SDK 与 FK 差很大 | 预期现象；双轴+数值差；不自动「校正」 |
| MuJoCo viewer 与 Wayland | 记录；必要时 `MUJOCO_GL=egl` 或 glfw |
| 同进程阻塞控制 | 默认旁路进程 + npz 总线 |
| HDF5 schema 不一 | 探测多种 key；失败给明确错误 |
