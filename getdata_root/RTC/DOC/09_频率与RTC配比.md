# 09 · 执行频率 / 推理延迟 / CHUNK 配比与调到 5 Hz

> 目的：在 **LIBERO 预训练 ≈20 Hz、真机数据 ≈30 Hz、现网 chunk `H=8`** 的前提下，  
> 说清怎样把部署调到 RTC 更合适的频率（例如 **5 Hz**），以及各方案的代价。  
> 配套：`04_P1挂载点清单.md` §6、`README.md`、训练手册 `docs/2026-08-07_StarVLA_ARX训练配置手册.md` §6.1.2。

---

## 1. 当前事实（不要混）

| 来源 | 动作时间粒度 | 备注 |
|------|----------------|------|
| LIBERO 预训练 | 约 **20 Hz** | 预训练动作「一步」≈50 ms |
| ARX 真机采集 | 约 **30 Hz** | 0806 Δ 配方：**30→20 Hz 下采样** 后再算相邻帧 Δ |
| 5694 现网 ckpt | 训练侧按 **~20 Hz 帧距** 学 Δ；`action_horizon H=8` | 一步输出 = 相邻训练帧之间的 ΔEEF |
| 部署控制环 | `eval_starvla_libero_x5.py --control_hz` | client 默认 RTC 侧常写 **5.0**；真机习惯 20–30 |

要点：

1. **ΔEEF 对频率敏感**：训练时 `Δ = pose[t+1]-pose[t]` 的物理时间跨度 ≈ `1/f_train`。  
2. 部署 `control_hz = f_deploy` 只改「多久发一步」，**不会自动改模型脑子里的步长语义**。  
3. RTC 约束（PI / LeRobot）：需要  
   \[
   H \gtrsim d + E,\quad d=\lceil T_{\mathrm{infer}}\cdot f_{\mathrm{deploy}}\rceil
   \]  
   其中 `E=execution_horizon`（本仓 T=8 时建议起步 **4**，勿盲目抄 LeRobot 的 10）。

## 2. 参考配比（论文 / LeRobot / RynnVLA）

| 来源 | Chunk | 频率/时间 | 延迟与重叠 |
|------|-------|-----------|------------|
| PI RTC | **50** 步 ≈ **1 s** | 隐含 ~50 Hz | 仍可抗 **>300 ms**；`d≈15` 时仍有裕度 |
| LeRobot π0 | `chunk_size=50` | 相机示例 30 fps | 示例 `inference_delay=4`；`execution_horizon≈8–12` |
| RynnVLA | `len_action` 5/10/20 | 跟数据帧率对齐 | **无 RTC 时序公式**；只保证训练 chunk 与数据一致 |

**对本仓的含义**：`H=8` 远小于 PI 的「约 1 s」，因此要么 **降低 `f_deploy`**，要么 **加大 H（重训）**，要么 **压低 `T_infer`**。三者至少做对一项，RTC 才有窗口。

粗算（`E=4`，`H=8`）：

| \(T_{\mathrm{infer}}\) | 合适 \(f\) 量级（需 \(d+E\le H\)） |
|------------------------|-------------------------------------|
| 0.3 s | \(d\le4\) → \(f\lesssim 13\,\mathrm{Hz}\)；稳妥 **5–10 Hz** |
| 0.5 s | \(d\le4\) → \(f\lesssim 8\,\mathrm{Hz}\)；稳妥 **5 Hz** |
| 0.9 s | \(d\le4\) → \(f\lesssim 4\,\mathrm{Hz}\)；先压延迟再谈 RTC |

## 3. 「理想 5 Hz」到底改什么

把部署调到 **5 Hz** 有三种完全不同的含义，必须先选一种：

| 代号 | 含义 | 模型 / 数据要不要动 |
|------|------|---------------------|
| **D1 仅控制环变慢** | `control_hz=5`，仍用现网 20 Hz 语义的 Δ | **不用重训**；墙钟运动变慢（约 20/5=4×） |
| **D2 控制环变慢 + 尺度补偿** | 5 Hz 执行，并用 `pos_scale/rot_scale`（或等价系数）放大 Δ，试图贴近原墙钟速度 | **不用重训**；近似、有过冲/抖风险 |
| **D3 训练语义也改成 5 Hz** | 数据按 5 Hz 重采样再算 Δ，或等价拉大帧距后重训 / 继续训 | **要改数据或重训**；语义最干净 |

RTC POC / 联调：**优先 D1**，先验证异步 + guidance；手感不够再考虑 D2；要长期 5 Hz 产品化再上 D3。

## 4. 方案清单（从快到慢）

### 方案 A — 部署降到 5 Hz（推荐 RTC 起步，对应 D1）

**做法**

```bash
# 真机 / dry-run：控制频率 5Hz；RTC 开
python3 lewm_x5_grasp/scripts/eval_starvla_libero_x5.py \
  --host 127.0.0.1 --port 5694 \
  --control_hz 5 \
  --rtc-mode track_b \
  --pos_scale 0.05 --rot_scale 0.5 \
  ...
```

RTC client 内 `control_hz` 用于：

- 控制循环睡眠 `dt=1/f`；
- `inference_delay ≈ ceil(T_infer * f)`（步）。

**预期**

- `f=5`，`T_infer≈0.3s` → `d≈2`；`E=4` → `d+E=6 ≤ H=8`，RTC 窗口够用。  
- 每步仍是「训练时 ~50 ms 的位移」，但每 200 ms 才走一步 → **任务变慢约 4 倍**，轨迹形状可仍合理。

**适用**：先把 `track_b` 跑稳、看断点是否平滑。  
**不适用**：要求与示教同速完成任务。

---

### 方案 B — 5 Hz + 尺度放大（对应 D2，谨慎）

**动机**：D1 太慢时，用部署侧放大补墙钟速度。

粗算（仅启发，需实机标定）：

\[
k \approx \frac{f_{\mathrm{train}}}{f_{\mathrm{deploy}}}
\quad\text{（例：20/5 = 4）}
\]

```text
# 示例：在原有 deploy scale 上再乘 k（或一次性改大）
--pos_scale 0.20   # 原 0.05 × 4
--rot_scale 2.0    # 原 0.5  × 4
```

**风险**

- Δ 不是严格线性可缩放；放大后易 **过冲 / 抖 / 夹爪时机错位**。  
- RTC leftover 在 server 侧是 **unnorm 后、scale 前** 物理量；client 积分时才乘 scale —— **不要**把已乘 scale 的量送回 `rtc_prefix`。  
- 夹爪是开合命令，**不要**乘 `k`。

**建议**：先 `k=2` 试半档，再冲到 4；并盯末端速度与安全限位。

---

### 方案 C — 坚持 ~20 Hz 部署（对齐训练，RTC 暂关或后置）

**做法**：`--control_hz 20`，`--rtc-mode off`，同步吃完 chunk。

**原因**：`H=8` 时 `d=ceil(0.3*20)=6`，`d+E` 已顶满或超 chunk，RTC 收益差甚至有害。

**适用**：要速度与训练语义一致、暂不依赖 RTC。  
**后续**：压 `T_infer` 到 ≪0.15 s，或方案 E 加大 H 后再开 RTC。

---

### 方案 D — 数据 / 训练侧统一到同一频率（对应长期正确）

目标：**`f_data ≈ f_train ≈ f_deploy`**，再谈 RTC。

#### D-a：继续以 20 Hz 为「标准节拍」（与现配方一致）

1. 真机 30 Hz → 转换时 **30→20 下采样**（现 0806 Δ 配方已如此）。  
2. 预训练 LIBERO 20 Hz：与微调帧距一致。  
3. 部署：优先 **20 Hz**（方案 C）；若开 RTC，需更大 H 或更低延迟。  
4. **不要**在未改数据的情况下假装模型是 5 Hz 语义。

#### D-b：真要产品化 5 Hz（D3）

1. **重算 Δ**：在 30 Hz 序列上按步长 `skip≈30/5=6`（或时间戳对齐）取帧，再算  
   `Δ = eef[t+skip]-eef[t]`（姿态仍用相对旋转，见训练手册 §6.1.2）。  
2. 写出新数据集（例：`*_delta_*_5hz`），`fps/meta` 标成 5。  
3. **重训或至少充分继续训**（动作分布变大，旧 20 Hz ckpt 不能直接当 5 Hz 语义用）。  
4. 部署 `--control_hz 5`，`pos_scale/rot_scale` 回到与训练写入一致的默认（通常 **不必**再乘方案 B 的 `k`）。  
5. 可选：同时把 `action_horizon` 提到 **16–50**（见方案 E），使 5 Hz 下 chunk 时间覆盖 ≥0.5–1 s，更接近 PI。

#### D-c：混训 LIBERO(20) + 真机(30→20)

- 混训时真机必须先抽到 **20 Hz**，避免同一 batch 里「一步」物理时间不一致。  
- 部署频率仍按 **20 Hz 语义**理解；降到 5 Hz 只走方案 A/B，不把混训数据改成 5 Hz 却沿用旧 ckpt。

---

### 方案 E — 加长 CHUNK（对齐 PI，重训）

| 目标部署频率 | 建议 `H`（约 0.5–1 s 覆盖） | 与 RTC |
|--------------|-----------------------------|--------|
| 5 Hz | 8～16（1.6～3.2 s 偏长可再调） | `H=8` 已够 RTC；加长主要提升开环前瞻 |
| 20 Hz | **20～50**（细则见 §4.1） | RTC 才有类似 PI 的裕度 |
| 30 Hz | **30～50** | 需更低延迟或更大 H |

加长 `action_horizon`：**必须重训**；只改推理配置无效。  
「少执行几步」（`n_action_steps < H`）不用重训，但 **更不利于** RTC 窗口。

---

### 4.1 锁定 20 Hz 时：`chunk_size` / `action_horizon` 怎么定

前提：训练与部署都按 **20 Hz**（LIBERO + 真机 30→20）；控制环 `--control_hz 20`。

**公式**

```text
d = ceil(T_infer_p50 * 20)          # 推理延迟（步）
E = execution_horizon                 # RTC 重叠，建议 8~12（对齐 LeRobot）；起步可 8
H_min_rtc = d + E                     # RTC 硬下界
H_rec     = max(20, 2*d + E)          # 推荐：约 ≥1s 前瞻，且留一倍延迟裕度
H_pi_like = 50                        # 对齐 PI/π0 常用档（20Hz 下 ≈2.5s）
```

**按现网延迟量级选 H（先估再训，训后重测）**

| 暖机 `T_infer` p50 | `d`@20 Hz | `H_min_rtc`（E=8） | **推荐训练 `H`** | 说明 |
|--------------------|-----------|---------------------|------------------|------|
| ≤0.15 s | ≤3 | 11 | **20** | 约 1 s chunk；RTC 裕度够 |
| ~0.30 s（现网常见） | 6 | 14 | **24～30** | 首选试 **24** 或 **30** |
| ~0.50 s | 10 | 18 | **30～40** | 先压延迟更划算 |
| ~0.90 s | 18 | 26 | **40～50** 或先降频 | H 很大且更慢；优先优化隧道/算力 |

**本仓默认落点（写进训练计划）**

| 项 | 取值 | 理由 |
|----|------|------|
| `control_hz` | **20** | 与训练帧距一致 |
| `action_horizon` / chunk_size | **先 24，备选 30** | 覆盖 `d≈6`+`E≈8` 且约 1.2–1.5 s；不必一步上 50 |
| `execution_horizon` | **8**（H≥24 后） | 对齐 LeRobot 常用 8–12；旧 H=8 时仍用 4 |
| `prefetch_remaining` | **≈ d+2** 或 **H/3** | 尽早异步重推，避免队列见底 |
| `num_inference_timesteps` N | 先保持 **4** | 加大 H 已增耗时；N 勿同时猛加 |
| 数据 fps | 仍 **20 Hz 语义** | 只加长未来窗口，**不改** Δ 帧距 |

**必须做 / 不要做**

1. **必须重训**（或从现网 ckpt 改 `action_horizon` 后充分继续训）；推理配置改 H **无效**。  
2. 数据 loader 的 action 切片长度与配置 `H` **一致**（不足尾部 pad/丢弃策略与现配方相同）。  
3. 训完后在目标机 **重测 `T_infer(H_new)`**，用新 p50 回代公式；若 `d+E > H` 再升到 30/40。  
4. **不要**在 H=8 的 ckpt 上把 20 Hz + RTC 当正式方案。  
5. 预期：`H`↑ → 单次推理略慢；以「重测后仍 `H ≥ d+E`」为准，而不是假设延迟不变。

**与 LeRobot/PI 对照**

- LeRobot 控制默认 **30 Hz**，π0 `chunk_size=50`（约 1.67 s）。  
- 换算到 **20 Hz、约 1～1.5 s**：`H≈20～30`，与上表「先 24、备选 30」一致。  
- PI 的 50@~50 Hz≈1 s；20 Hz 上抄 50 会到 2.5 s，可用作上限，不是第一步必选项。

## 5. 推荐决策树（本仓）

```text
要开 RTC（H=8，现网延迟 ~0.3s）？
├─ 是 → 方案 A：control_hz=5，rtc-mode=track_b，scale 先保持训练默认
│        ├─ 太慢 → 方案 B：小步放大 pos/rot scale（夹爪不动）
│        └─ 要长期 5Hz 同速 → 方案 D-b 重采样 + 重训
└─ 否 → 方案 C：control_hz=20，rtc off（对齐 20Hz 训练语义）
         └─ 仍要 RTC@20Hz → 方案 E 加大 H 和/或压 T_infer
```

**近期默认建议**

| 阶段 | 频率 | RTC | scale |
|------|------|-----|-------|
| RTC 联调 / 平滑验证 | **5 Hz** | `track_b` | 训练默认（D1） |
| 正常任务速度、暂无 RTC | **20 Hz** | `off` | 训练默认 |
| 未来 RTC@20 Hz | 20 Hz | `track_b` | 默认 + **H≥20 重训** 或延迟 ≪0.15 s |

## 6. 验收清单（调频率时必做）

1. **暖机测 `T_infer`**（双图 + 隧道）：记 p50 / p95。  
2. 算 `d=ceil(T_infer * control_hz)`，确认 `d + execution_horizon ≤ H`（现网 H=8）。  
3. 日志：`rtc={..., srv: True}`，`delay` 与预期一致。  
4. ΔEEF：对比同任务下末端轨迹；改 `control_hz` 后若变慢，属 D1 预期。  
5. 若用方案 B：单独记一组 scale，避免和「训练默认 0.05/0.5」混淆。  
6. 夹爪：始终命令语义，不随频率比例缩放。

## 7. 与代码开关的对应

| 旋钮 | 位置 | 调频率时怎么动 |
|------|------|----------------|
| `--control_hz` | `eval_starvla_libero_x5.py` / `RTCDeltaEefClient` | 5 = RTC 起步；20 = 对齐训练 |
| `--rtc-mode` | 同上 | 5 Hz 可 `track_b`；20 Hz+H=8 建议先 `off` |
| `--pos_scale` / `--rot_scale` | 同上 | D1 不动；D2 才放大；D3 与训练写入一致 |
| `execution_horizon` / `prefetch_remaining` | RTC client | T=8 时 horizon 先 4；prefetch 尽早 |
| 数据 fps / 下采样 | 转换脚本 + 训练手册 §6.1 | 只在 D-b / D-c 动 |
| `action_horizon` | 训练配置 | 只在方案 E 动（重训） |

## 8. 一句话

- **LIBERO 20 Hz + 真机 30→20**：训练语义是 **20 Hz 一步**；部署 5 Hz 是 **同一 Δ、更慢地执行**（方案 A），不是免费变成「5 Hz 模型」。  
- **RTC 理想窗口**：现网 `H=8` → 先 **5 Hz + track_b**；要 **20 Hz + RTC** → 加长 chunk 或降延迟。  
- **真要 5 Hz 且同速**：按方案 **D-b** 重采样算 Δ 并重训，不要只改 `control_hz` 假装对齐。
