## P6 · 20 Hz 控制 + 加长 chunk（RTC 正式档）

**目标**：部署 `--control_hz 20`（对齐 LIBERO/真机 20 Hz 语义）时，把输出 `chunk_size`/`action_horizon` 调到 RTC 可用，而不是继续用现网 `H=8`。

**选型（细则见 [`09_频率与RTC配比.md`](./09_频率与RTC配比.md) §4.1）**

| 项 | 计划值 |
|----|--------|
| `control_hz` | **20** |
| `action_horizon` H | **先 24，不达标再 30**（上限参考 50） |
| 计算公式 | `d=ceil(T_infer*20)`，需 `H ≥ d + E`；推荐 `H ≥ max(20, 2d+E)` |
| `execution_horizon` E | **8**（H≥24 后）；现网 H=8 阶段仍用 4 |
| 数据 | **不改** 20 Hz 帧距 / Δ 定义；只加长未来 action 窗口 |
| 训练 | **必须**按新 H 重训或充分继续训；禁止只改推理配置 |

**现网延迟对照（选型锚点）**

| `T_infer` p50 | d@20 Hz | 最低 H（E=8） | 计划采用 |
|---------------|---------|---------------|----------|
| ~0.30 s | 6 | 14 | **H=24**（首选） |
| ~0.50 s | 10 | 18 | **H=30** |
| ≥0.90 s | ≥18 | ≥26 | 先压延迟，或 H=40～50 |

- [ ] 暖机测当前 H=8 的 `T_infer` p50/p95（双图+隧道），填上表选 H  
- [ ] 训练配置：`action_horizon`（及 dataloader 切片）改为 **24**（或上表结果）  
- [ ] 数据侧确认：仍 30→20 下采样算 Δ；episode 尾部对 H 的 pad/丢弃与现配方一致  
- [ ] 提交重训 / 继续训；得到新 eef ckpt（新端口或替换 5694 前备份）  
- [ ] 新 H 上重测 `T_infer`；验证 `ceil(T_infer*20)+8 ≤ H`  
- [ ] 部署：`--control_hz 20 --rtc-mode track_b`，`execution_horizon=8`，`prefetch_remaining≈d+2`  
- [ ] 对比 H=8@5 Hz RTC vs H=24@20 Hz RTC：平滑、任务耗时、是否断流  
- [ ] 更新 `09` 实测表 + README 推荐命令  

**完成定义**：20 Hz 下 RTC `applied=True` 且 `d+E≤H`；文档写明最终 H 与实测延迟。
