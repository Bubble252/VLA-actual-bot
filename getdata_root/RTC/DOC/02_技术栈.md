## 2. 两套路径对应的技术组件

### 2.1 轨 A：工程 RTC（后处理，优先）

适用于：**只能拿到最终 action chunk** 的现网 StarVLA。

```text
旧 leftover + 新 chunk + delay
  -> hard/soft mask
  -> stitch / soft overlap
  ->（可选）关节 B-spline / min-jerk / 限幅
  -> IK（若是 pose）或直接关节下发
```

| 组件 | 职责 | 候选落点 |
|------|------|----------|
| `ChunkBuffer` / leftover | 记录未执行动作与已执行步数 | 本机 client 或 `RTC/` 新模块 |
| `LatencyEstimator` | 用 RTT / 推理耗时估计 delay（步数） | 对照 LeRobot `LatencyTracker` |
| `SoftOverlapStitcher` | overlap 区加权融合 / 冻结前缀 | 对照 `rtc_demo` + 论文 soft mask |
| `SafetyClamp` | 速度/加速度/关节增量限幅 | 复用平滑策略文档中的工程项 |
| 验证脚本 | naive vs soft 指标对比 | `RTC/` 实验脚本（待建） |

不需要改远端 DiT 采样循环；可与现有 websocket client 并行演进。

### 2.2 轨 B：完整 RTC（生成期 guidance，中期）

适用于：能进入 **flow-matching Euler / denoise 每一步** 的策略。

```text
obs -> VLM 条件
    -> 对 action 轨迹做多步 Euler
         每步：v = DiT(...); 叠加 RTC prefix guidance
    -> 输出与旧 leftover 对齐的新 chunk
```

| 组件 | LeRobot 对应 | StarVLA 对应（需改造） |
|------|--------------|------------------------|
| 配置 | `RTCConfig` | 新建服务端/配置项（enabled、horizon、guidance 权重） |
| Guidance | `RTCProcessor.denoise_step` | 插入 `FlowmatchingActionHead.predict_action` 的 Euler 环 |
| 队列 | `ActionQueue` | server 或 client 双侧异步队列 |
| 相对动作重锚 | `reanchor_relative_rtc_prefix` | 仅当动作是 relative 时需要；当前远端有 joint 绝对 / eef 等，需按权重区分 |
| 调试 | `Tracker` / visualizer | 可选：保存 guidance 前后 chunk 曲线 |

**注意**：轨 B 与 LeRobot 源码算法同族，但 **不能 pip 安装后直接 import 接到 websocket**；要在 StarVLA 进程内移植或做适配层。

## 3. 关键算法与技术点

### 3.1 RTC 核心概念

| 术语 | 含义 |
|------|------|
| action chunk | 一次推理输出的未来多步动作序列 |
| inference delay | 从发起推理到新 chunk 可用，期间已执行的步数 |
| leftover / prefix | 旧 chunk 中仍将执行、或已确定要冻结的前缀 |
| execution horizon | 希望与旧轨迹强对齐的重叠长度 |
| prefix attention / soft mask | 对 overlap 区施加随时间衰减的约束强度 |
| guidance / inpainting | 在 flow/diffusion 积分过程中把 prefix 当已知条件 |

### 3.2 LeRobot RTC 目录要点

路径：`LEROBOT/lerobot-main/src/lerobot/policies/rtc/`

| 文件 | 技术作用 |
|------|----------|
| `modeling_rtc.py` | `RTCProcessor`：denoise 步内 prefix guidance |
| `configuration_rtc.py` | `enabled`、`execution_horizon`、`max_guidance_weight`、attention schedule |
| `action_queue.py` | 线程安全队列；RTC 开时按 delay 替换并保留 leftover |
| `latency_tracker.py` | 延迟滑动窗口统计 |
| `relative.py` | 相对动作 leftover 重锚到当前状态 |
| `debug_*.py` | 调试记录与可视化 |

### 3.3 StarVLA 侧关键调用链（远端）

```text
websocket infer
  -> PolicyServerWrapper.predict_action
  -> Qwen_GR00T.predict_action
  -> FlowmatchingActionHead.predict_action
       # noise init
       # for step in num_inference_timesteps:
       #     pred_velocity = DiT(...)
       #     actions += dt * pred_velocity
  -> 返回 (B, T, action_dim) 最终 chunk
```

轨 B 的挂载点应在 **Euler for-loop 内部**，而不是仅在返回值上做加权平均。

### 3.4 动作空间差异（影响 mask / IK）

| 远端服务 | 动作含义 | RTC 后处理注意 |
|----------|----------|----------------|
| 5794 joint | 关节角(+夹爪) chunk | 可在关节空间 soft overlap；更贴近执行平滑 |
| 5694/5695 eef | Δ/绝对末端(+夹爪) | overlap 可在 pose 空间；下发前仍走 IK / 差分路径 |
| 夹爪 | 多为命令语义 | 通常不宜与连续关节/位姿同一套平滑；需单独规则 |

## 6. 风险与约束

1. **接口黑盒**：现网只返回最终 chunk → 完整 RTC 无法仅在本机 client 实现。  
2. **依赖冲突**：`lerobot[pi]` 常拉专用 transformers 分支，易与 SmolVLA / 其他栈冲突。  
3. **chunk 很短**：当前 `action_chunk_size=8`，overlap / horizon 超参空间比论文 50-step 设定更紧。  
4. **异步与安全**：异步换 chunk 时必须处理超时、空队列、急停；真机前先仿真。  
5. **夹爪语义**：开合命令与连续轨迹平滑要分流，避免被 soft mask 抹成中间态。
