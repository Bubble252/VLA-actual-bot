## 1. 主根因：rot_delta 旋转语义错位（#1）

### 证据链（数值对账，2026-10-10 录制轨迹）

- 模型输出 rot_delta[0] = **−5.83 mrad/步**
- 实际 state rotvec[1] 漂移 = **−5.81 mrad/步**（完美对应）
- 模型 dz = −1.0~−1.6mm/步（下降指令），实际 z 却 +0.66mm/步
- x 方向精确追踪罐子（相关 0.46），姿态越漂模型输出越退化（state OOD 恶性循环）

### 机理

- 训练 action = state rotvec **逐元素差分** → 模型 rot_delta 语义 = **世界系旋转向量增量**
- client（0813 遗产路径）把 rot_delta **当 extrinsic-XYZ 欧拉增量**逐元素加到 rpy
- home 姿态 yaw=90°，此时欧拉 roll 增量物理效果 = 绕世界 **y** 旋转（`Rz(90°)Rx(δ)Rz(−90°)=Ry(δ)`）
- → roll 命令被执行成 pitch 漂移 → rotvec OOD → 输出退化 → "乱飘"

### 责任归属（重要认知，勿再争论）

- 出错代码是 **0813 遗产**，但 0813 当时未炸是因为 yaw≈0 附近两套语义几乎重合（哑弹未触发）
- **"0813 已验证"≠执行层普适正确**。换配方（ljn rotvec-diff action + yaw=90° 起始）必须重新对账 action 应用语义——这是我们迁移适配的遗漏

### 修复（已完成，待真机复验）

- `rotvec_delta_to_euler_increment()`：R_new = Rv(δ)@R_cur（世界系前置乘）→ wrap(欧拉差)
- 单元测试：yaw=90° 下 world−x 5.8mrad → euler pitch +5.8mrad ✓；任意倾斜姿态还原误差 1e-16 ✓

## 1.5 数据裁决实验（2026-10-14，offline_eval 问题的回答 + 决定性证明）

**背景**：101 上有 `offline_eval_arx_pick.py`（开环 MSE：expert state → model → 与 expert action 比误差）。它按构造原理测不出执行层闭环 bug（expert state 永远在分布内，模型离线干净不代表执行正确——已验证：MSE 7.2e-5 漂亮但真机乱飘），**不能单独证明部署代码正确**；但其 norm_stats 可交叉核对我们的 unnorm 常数。

**决定性思路**：demo 数据本身就是 ground truth——`state_{t+1}` 是 `action_t` 在正确语义下执行的产物。用两种假设从 `state_t + action_t` 重构 `state_{t+1}` 的旋转，哪个误差小哪个就是训练契约。脚本 `/tmp/test_rot_semantics.py`（101，pyarrow 读 parquet，5 集 1512 对相邻帧）：

```
语义A 世界系rotvec前置乘 Rv(a)@R(s):  mean=0.0000 mrad  max=0.0000 mrad   ← 机器精度级精确
语义B 欧拉逐元素增量 rpy(s)+a:         mean=12.4  mrad  max=95.4 mrad     ← 与真机漂移速率同量级
平移 sanity ||Δstate_xyz − a_xyz||:     mean=0.000000 m                   ← 平移 delta 契约同时确认
```

**结论**：
1. 训练契约 = **`R(state_{t+1}) ≡ Rv(action_rot) @ R(state_t)`（世界系 rotvec 前置乘），精确成立**（并非此前认为的"逐元素差分"——机器精度下逐元素差分应有二阶小残差，实测为零，说明数据管线的 action 就是按精确相对旋转生成的）
2. 语义B（0813 旧行为）每步 12.4 mrad 的错误旋转注入正是真机漂移之源
3. 我们的修复 `rotvec_delta_to_euler_increment()` 实现的正是语义A（单元测试还原误差 1e-16）→ **模型侧契约已被数据证明正确**，无需真机即可确信转换方向
4. 剩余未证明的：真机 state 采集链路、diff-IK 硬件执行、RTC 时序 → 仍需 §3 真机复验
